# Тестовый стенд

## Что разделено

- Тестовая таблица и Script ID записаны в
  [конфигурации](../config/environments/test.json). Секретов в этом файле нет.
- CI APK: `ru.coffeepoint.ci`, отдельные локальные данные, версия с суффиксом `-ci`.
- CI APK читает URL и токен только из тестовых настроек сборки. Без них
  синхронизация отключена, перехода на рабочий API по умолчанию нет.
- Команды управления терминалами Vendista в CI APK блокируются до сети.
- Рабочая сборка без `-PciBuild=true` сохраняет прежние настройки.

Копия таблицы не является готовым сервером. До публикации отдельного Apps Script
и настройки URL/токена тестовый APK может работать только с локальными данными.
Не вводите в нём реальные операции: накопленные локальные изменения могут
отправиться после настройки тестового сервера и обновления APK.

## Подготовка серверных файлов

```powershell
node scripts/prepare-test-backend.cjs
```

Результат: `.codex/apps-script-test/`, вне Git. Скрипт копирует серверные `.gs`
и manifest, подменяет конфигурацию на тестовую и создаёт `.clasp.json` для
тестового Script ID. Рабочие исходники не меняются, файлы никуда не отправляются.
Скрипт откажется использовать ID рабочей таблицы или рабочей папки фотографий.

Папка тестовых фото пока не задана: загрузку фото не использовать.
Для неё позже потребуется отдельная папка Drive и `rootFolderId` в конфигурации.

## Однократное подключение Google

Потребуется авторизация владельца проекта в официальном CLI `@google/clasp`
и включённый Apps Script API в настройках Google. Авторизационные файлы
не добавлять в Git и не передавать в чат.

В терминале компьютера выполнить и пройти вход самостоятельно:

```powershell
.\scripts\Invoke-TestClasp.ps1 login
```

Обёртка [Invoke-TestClasp.ps1](../scripts/Invoke-TestClasp.ps1) использует
официальный `@google/clasp@3.4.1` через npm/pnpm и запускает его из подготовленной
тестовой папки. Поддерживается также bundled pnpm текущего Codex на Windows.
CLI открывает Google для выдачи разрешений; эти действия выполняет владелец
аккаунта. Подготовленная папка уже содержит ID отдельного тестового проекта.
Для ручного запуска без обёртки допустим `npx @google/clasp@3.4.1 login`.

После авторизации загрузить подготовленные файлы именно в тестовый проект,
создать отдельное web-app развёртывание и задать его Script Properties:

- `SYNC_TOKEN`: отдельный тестовый токен, отличный от рабочего.
- `VENDISTA_TOKEN`: нужен только для проверки серверных отчётов/триггеров;
  запросы отчётов читают реальные продажи, но начисления пишутся в тестовую таблицу.

Триггеры тестового проекта не создаются скриптом подготовки. Для начала
достаточно ручной проверки; параллельные запросы тестовых и рабочих триггеров
к Vendista используют общие лимиты API. Не копировать расписание без необходимости.

## Настройки Android CI

В GitHub → Settings → Secrets and variables → Actions:

- Variable `TEST_SHEETS_WEB_APP_URL`: URL тестового web-app с окончанием `/exec`.
- Secret `TEST_SHEETS_SYNC_TOKEN`: тот же тестовый токен, что в Script Properties.

После изменения настроек запустить новый Android CI. Уже собранный APK не меняется:
конфигурация вшивается при сборке. Для локальной тестовой сборки эти значения
передаются через переменные `COFFEEPOINT_TEST_WEB_APP_URL` и
`COFFEEPOINT_TEST_SYNC_TOKEN`, затем выполняется Gradle с `-PciBuild=true`.

`build-info.json` содержит `backendEnvironment`, `backendConfigured` и
`terminalCommandsEnabled`, но не токен. `backendConfigured` означает только
наличие настроек, а не успешную проверку сервера.

## Перед использованием

1. Проверить в подготовленном `Config.gs` ID тестовой таблицы и в `.clasp.json` Script ID.
2. Проверить GET `full_sync` тестового развёртывания.
3. Собрать CI APK и выполнить тестовую операцию.
4. Убедиться, что изменился только тестовый лист, а рабочая таблица не изменилась.

Шаги 2–4 требуют опубликованного тестового сервера; наличие копии таблицы
и успешных локальных тестов их не заменяет.
