# Модальные окна

Общие компоненты находятся в
[AppDialogs.kt](../app/src/main/java/ru/coffeepoint/shared/component/AppDialogs.kt).
Для новых окон не использовать `AlertDialog` или системный `TimePickerDialog`
непосредственно в экране.

## Правила

- `AppDialog`: фон из темы, радиус 16dp, стандартные отступы Material 24dp.
  Заголовок `headlineSmall` (24sp), основной текст `bodyMedium` (14sp).
- Длинное содержимое прокручивается отдельно, не вытесняя действия. Общий
  контейнер уже содержит прокрутку: не добавлять вторую вертикальную прокрутку
  или бесконечный `LazyColumn` внутрь его `text`.
- `AppDialogButton`: высота не меньше 48dp, радиус 8dp, заглавные буквы,
  выравнивание по центру, внутренние отступы 8dp по горизонтали и 12dp по вертикали.
  Подпись короткая; шрифт подбирается в диапазоне 12–14sp для одной строки.
- Основное действие выделено цветом темы, вторичное — контуром.
  Красная заливка `Destructive` только для удаления, не для «Продолжить».
- `AppDialogActions`: две равные колонки с промежутком 12dp. Одна кнопка занимает
  всю ширину. При трёх действиях отмена расположена отдельной строкой ниже.
- Подписи отмены едины: «Отменить», для информационного окна — «Закрыть».
  Закрытие по Back/внешнему нажатию вызывает прежний `onDismissRequest`.
- `AppDatePickerDialog` сохраняет стандартный календарь, ограничения дат и
  доступность выбора. Его кнопки используют тот же UI-kit.
- `AppTimePickerDialog` использует Compose `TimeInput`, 24-часовой формат и
  те же кнопки. Изменение времени применяется только при подтверждении.
- `SyncSendingOverlay` остаётся отдельным блокирующим индикатором без действий;
  это не окно ошибки или подтверждения.

## Проверенные окна

| Семейство | Где применяется |
| --- | --- |
| Ошибки получения данных | Список станций, заработок, каталог |
| Ошибки отправки и локальное сохранение | Станция, обслуживание, склад, настройки, каталог |
| Подготовка обслуживания | Повторить / Продолжить и отдельная отмена |
| Подтверждение удаления | Станция и вариант закупки |
| Информация | Варианты закупки и схема кнопок аппарата |
| Команды | Управление терминалом |
| Обновление APK | Предложение, скачивание, установка и ошибка |
| Дата и время | Заработок, аренда, узлы обслуживания, часы посещения |

Бизнес-действия, права ролей, повторные запросы и ограничения выбора не переносятся
в UI-kit. Они остаются в своих экранах и ViewModel.

UI-тесты: `AppDialogsTest`, `ServicePreparationErrorDialogTest`,
`SyncSendingErrorDialogTest`. Они проверяют расположение действий, независимость
обработчиков, disabled-состояние, длинный каталог/текст, увеличенный шрифт и выбор
даты/времени. Это не полное ручное покрытие всех экранов на всех устройствах.
Node-проверка `scripts/tests/ui-kit.test.cjs` запрещает прямые вызовы базовых
диалогов за пределами UI-kit; она добавлена в Android CI и проверку выпуска.
