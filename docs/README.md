# Документация CoffeePoint

## Порядок знакомства

1. [Карта папок](project-structure.md): найти экран, данные или интеграцию.
2. [Архитектура](architecture.md): понять ответственность компонентов.
3. [Бизнес-процессы](business-processes.md): проверить сценарии и роли.
4. [Синхронизация](synchronization.md) и [модель данных](database.md): менять сохранение и обмен данными.
5. [API и автотесты](api-endpoints.md): проверить сетевой контракт.
6. [Релизы](releases.md): собрать и опубликовать версию.

[Известные ограничения](known-limitations.md) описывают фактические пробелы,
а не запланированное поведение.

## Как обновлять документацию

Документацию меняем вместе с кодом в том же коммите или pull request:

- Новый экран или перенос папки: обновить карту проекта и README модуля.
- Изменение процесса: обновить бизнес-процессы и состав отправляемых данных.
- Изменение таблицы или поля: обновить модель данных, обе стороны интеграции,
  [контракт схемы](../app/src/test/resources/contracts/sheet-schema.json) и тесты.
- Изменение запроса: обновить реестр API и сценарий проверки.
- Изменение расписания: обновить страницу синхронизации и серверный README.
- Исправление ограничения: убрать или скорректировать соответствующий пункт.

Не дублируем все методы и строки кода: фиксируем ответственность, точки входа,
правила и последствия изменений. Ссылки в файлах относительные, чтобы они
работали на GitHub и в локальной копии репозитория.
