## Как обновлять документацию

Документацию меняем вместе с кодом в том же коммите или pull request:

- Новый экран или перенос папки: обновить карту проекта и README модуля.
- Изменение процесса: обновить бизнес-процессы и состав отправляемых данных.
- Изменение таблицы или поля: обновить модель данных, обе стороны интеграции,
  [контракт схемы](../app/src/test/resources/contracts/sheet-schema.json) и тесты.
- Изменение запроса: обновить реестр API и сценарий проверки.
- Изменение расписания: обновить страницу синхронизации и серверный README.
- Исправление ограничения: убрать или скорректировать соответствующий пункт.

Не дублируем все методы и строки кода: фиксируем ответственность, точки входа,
правила и последствия изменений. Ссылки в файлах относительные, чтобы они
работали на GitHub и в локальной копии репозитория.

## Автоматические проверки

Нужны Node.js 22 и Git; установка npm-пакетов не требуется. После изменения
`versionCode` или `versionName` в Gradle обновите генерируемый блок:

```powershell
node scripts/docs.cjs --write
```

Проверьте документацию перед отправкой:

```powershell
node --test scripts/tests/docs.test.cjs
node scripts/docs.cjs --check
```

Скрипт проверяет соответствие версии Gradle и существование локальных файлов
и папок в Markdown-ссылках (включая изображения и определения ссылок).
Внешние URL и якоря заголовков не проверяются. Файлы берутся из Git и новых
неигнорируемых файлов; артефакты сборки не включаются.

[Workflow Documentation](../.github/workflows/documentation.yml) запускает эти
проверки при push и Pull request. Он не меняет файлы и не проверяет смысловую
актуальность описаний. При устаревшей версии выполните `--write` и отправьте
изменённый файл в тот же PR. Чтобы ошибка блокировала слияние, в настройках
защиты ветки GitHub нужно сделать проверку `Version and local links` обязательной.

[Шаблон Pull request](../.github/pull_request_template.md) напоминает обновить
документацию или объяснить, почему она не затронута. GitHub применяет шаблон
из основной ветки: для автоматического появления его сначала нужно слить
из `test` в `master`. Существующее описание PR автоматически не заменяется.
