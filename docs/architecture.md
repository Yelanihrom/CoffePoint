# Архитектура

Проверено по исходникам на 20.10.2026.

## Путь данных

Экран читает состояние ViewModel. ViewModel обращается к репозиторию, который
читает и изменяет Room. Для обмена с сервером репозитории используют Google
Sheets connector. У ряда компонентов есть зависимости от Android Context;
полного выделения независимого domain-слоя в проекте нет.

При сохранении станции или склада сначала меняется локальная запись и
ставится признак ожидания синхронизации. Прямой запрос пытается отправить
результат сразу. Фоновый воркер позже обрабатывает оставшиеся записи.
Каталог имеет отдельный сценарий сохранения и не включён в фоновую отправку.

При импорте приложение получает данные из Apps Script и сохраняет их в Room.
Уведомления рассчитываются на устройстве после успешного фонового импорта.
Это локальные Android-уведомления; серверной доставки через FCM здесь нет.

## Продажи и заработок

Apps Script получает отчёты Vendista и записывает продажи после последней
заправки в `coffee_station`. Отдельный ежедневный триггер создаёт начисления
в `employees_transactions`. Android загружает готовые значения через `full_sync`.

Прямой Android-клиент Vendista сохранён для команд терминалу: перезагрузка,
включение и выключение экрана. Эти команды не проходят через Google Sheets.

## Роли

`MANAGER`, `OPERATOR`, `SUPPLY_OPERATOR` определяют доступные элементы интерфейса.
Выбранная роль хранится локально в `RolePreferences`. У управляющего отдельное
главное меню с переходами к представлениям оператора и снабженца.

Роль не равна сотруднику. Экран заработка пока использует первого активного
сотрудника; отдельного выбора личности при входе ещё нет. Apps Script проверяет
общий токен приложения и не получает отдельную учётную запись каждой роли.

## Границы изменений

- Логику экранов размещаем в соответствующем `feature`; повторно используемые
  кнопки, лоадеры и счётчики — в `shared/component`.
- Формат JSON и преобразования Google Sheets меняем в connector, а не в Compose.
- Изменение Room требует миграции. Изменение серверной схемы требует обновления
  листа, `Config.gs`, контрактов и опубликованного развертывания.
- Завершение обслуживания использует отдельные наборы полей. Общий upsert станции
  не должен отправлять серверные счётчики продаж.
- Сохранение в GitHub не публикует Apps Script и не обновляет установленный APK.
