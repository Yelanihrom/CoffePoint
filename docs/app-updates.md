# Обновления приложения

Рабочая сборка при запуске проверяет последний опубликованный стабильный релиз
через `GET https://api.github.com/repos/Yelanihrom/CoffePoint/releases/latest`.
Запрос не блокирует экран. Успешная проверка выполняется не чаще раза в сутки,
после ошибки следующая попытка возможна через час при новом запуске приложения.
Кнопка «Позже» откладывает предложение на сутки. CI-сборка проверку не выполняет.

На обоих экранах списка станций (оператор/снабженец, включая управляющего)
внизу закреплена версия из `BuildConfig.VERSION_NAME` и текстовая ссылка
«Проверить обновление» без подложки. Ручной запрос использует ту же Activity-scoped
`AppUpdateViewModel` и обходит интервалы автоматической проверки, отложенное
предложение и кеш кандидата. Одновременные проверки/скачивание не дублируются.
При наличии обновления открывается существующее окно, при отсутствии или ошибке
показывается результат рядом со строкой версии. В тестовой сборке нажатие
только объясняет ограничение; запрос к рабочему каналу не отправляется.

Релиз должен содержать `update.json` и APK, созданные [процессом выпуска](releases.md).
Приложение сравнивает `versionCode`, applicationId, минимальную версию Android и
сертификат установленного приложения. Старые релизы без манифеста игнорируются.
Доступный кандидат сохраняется локально для повторного предложения.

После согласия пользователя APK скачивается в приватный кэш `updates/` с прогрессом
и возможностью отмены. Проверяются размер, SHA-256, сведения APK и подпись.
При ошибке частичный файл удаляется, предлагается повторить скачивание.
Установщик Android открывается через FileProvider. На Android нужно разрешить
установку из этого источника и подтвердить обновление; тихой установки нет.
БД не очищается. Совместимость обновления требует прежнего ключа подписи.

## Публикация

GitHub-токен в приложение не добавляется. Репозиторий публичный, релизы с APK
и манифестом доступны анонимно. Ошибка проверки не мешает работе приложения.

Необходимо отозвать и заменить секреты из
исходников и истории Git, удалить их из истории и проверить логи/артефакты.
Одна новая правка файлов не скрывает старые коммиты. Безопаснее оставить код
приватным и завести отдельный публичный репозиторий только для APK и манифеста;
это потребует сменить адреса в клиенте и процессе выпуска.

## Проверки

`AppUpdateTest` проверяет версии, сертификат манифеста, SDK, адреса, периодичность,
контракт GitHub, отсутствие авторизации, скачивание, контрольную сумму и очистку
ошибочных файлов на локальном HTTPS-сервере. Системный установщик, разрешение
источника, поворот экрана и обновление поверх установленного APK требуют
ручного теста на устройстве. Публичные APK и манифесты предыдущих выпусков
проверены анонимным скачиванием; это не заменяет тест установки на телефоне.
`AppVersionFooterTest` проверяет ссылку, состояние проверки, сообщения и узкую
ширину с увеличенным шрифтом. Ручной обход интервалов покрыт `AppUpdateTest`.
