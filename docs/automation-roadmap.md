# Автоматизация: состояние и следующие шаги

Снимок на 20.10.2026. Наличие пункта в плане не означает, что он реализован.

## Уже работает

| Область | Реализация |
| --- | --- |
| Документация | Генерация блока версии из Gradle, проверка его актуальности и локальных ссылок в GitHub Actions |
| Правила PR | Шаблон с проверками и пунктом об изменениях документации |
| Агент | [AGENTS.md](../AGENTS.md): навигация, безопасные окружения и проверки перед завершением задачи |
| Серверные тесты | Node.js-контракты на таблицах в памяти, без live-запросов |
| Android | JVM-тесты с MockWebServer и проверки изоляции CI-конфигурации |
| Сборка | CI APK при push в `test` и PR, отчёты, сведения о коммите и контрольная сумма |
| Стенд | Отдельные таблица и Apps Script; live-чтение и запись проверены вручную, не отдельным CI job |

## Тесты: осталось

| Приоритет | Работа | Критерий готовности |
| --- | --- | --- |
| 1 | Автоматический read-only smoke тестового развёртывания | Отдельный workflow проверяет отказ без токена, `full_sync`, поля и типы; не использует рабочий URL и не раскрывает токен |
| 1 | Критичные бизнес-правила | Тесты расчёта поставки, min/max, взаиморасчёта и периодов, смены роли, повторной отправки и защиты от повторного списания |
| 1 | Серверные ежедневные начисления | Даты по Москве, привязки сотрудников, исключения станций, повторный запуск и пересечение периодов проверены без настоящих запросов Vendista |
| 2 | Room и миграции | Экспорт схем и миграционные тесты: обновление приложения сохраняет данные и pending-статусы |
| 2 | WorkManager | Тесты сети, retry/backoff, конфликтов, pending-данных, разделения импорта/отправки и правил уведомлений |
| 2 | UI-тесты на эмуляторе в CI | Основные сценарии оператора/снабженца и офлайн-повтор с контролируемым тестовым источником данных |
| 3 | Live-запись в тестовую таблицу | Изолированные фикстуры, защита от конкурентного запуска и восстановление при ошибке; тест не портит данные ручного стенда |

В серверных тестах остаётся TODO для удаления каталога: Android отправляет
`delete`, а текущий сервер его не обрабатывает. Это функциональный пробел,
не завершённый автотест. Подробности — в [ограничениях](known-limitations.md).

Live-проверки с секретами нельзя запускать для произвольного непроверенного
PR-кода. Начать с ручного запуска workflow на проверенной ветке, затем отдельно
согласовать расписание или запуск после публикации сервера. UI-тесты и проверки
полей на реальном API решают разные задачи, один вид не заменяет другой.

## Документация: осталось

| Приоритет | Работа | Критерий готовности |
| --- | --- | --- |
| 1 | Проверять связь изменений кода и документов в PR | CI напоминает о затронутых разделах и требует обновления либо обоснованного исключения; не генерирует вымышленные описания |
| 2 | Якоря и оформление Markdown | Проверяются ссылки на заголовки, базовое оформление и корректность UTF-8; текущий скрипт проверяет только локальные пути и версию |
| 2 | Технические разделы API и БД | Автогенерация таблиц полей/параметров из проверяемых исходников; бизнес-смысл и независимые тестовые ожидания не заменяются генерацией |
| 3 | Описание релизов | Генерация черновика из PR с ручным подтверждением; не смешивать changelog с документацией текущего поведения |

Смысловую корректность бизнес-описаний CI пока не проверяет. `AGENTS.md` задаёт
правило обновлять документацию вместе с кодом, но сам по себе это не гарантирует
и не заменяет проверку изменений человеком.

## Отдельно от тестов

- Подтвердить обязательные проверки и PR в защите `master`. Проверка этих
  настроек через текущий GitHub API-доступ вернула 403; состояние не установлено.
- Настроить постоянную подпись и выпуск рабочего APK в Releases.
- Автоматизировать публикацию Apps Script из Git сначала в тестовое окружение.
  CLI и авторизация есть, публикация выполнялась вручную, CD workflow ещё нет.
