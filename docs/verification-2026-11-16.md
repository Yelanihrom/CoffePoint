## Условия рабочего переноса

Пользователь выбрал согласованное окно с обновлением всех сотрудников,
без временной поддержки старых APK. При подготовке PR окно ещё не было начато;
его подтверждённое выполнение зафиксировано ниже.

1. Перед переключением остановить обслуживание на телефонах и доотправить
   pending-изменения старых клиентов. Не удалять локальные БД для очистки очереди.
2. Сохранить свежие рабочие листы, исходники HEAD, опубликованную версию и список
   триггеров. Проверить ID из `config/environments/production.json`.
3. Подготовить рабочий `station_maintenance`: по шесть типов на станцию,
   исходные даты без выдуманного времени; счётчики и время расчёта пустые.
   Перед удалением колонок повторно сверить даты под блокировками.
4. Переключить рабочую схему и сервер согласованным снимком из `master`.
   Сохранить deployment ID/URL, токены и действующие расписания. `Config`
   должен загружаться до файлов, использующих его при инициализации.
5. Проверить независимые заголовки/данные и все коллекции рабочего `full_sync`.
   Установить только новый суточный триггер узлов, не дублируя существующие.
6. Назначить следующую версию Android, собрать подписанный APK прежним ключом,
   выпустить новым тегом и обновить все телефоны до возобновления обслуживания.
   Системную установку и импорт проверить на устройстве; старые APK не использовать.

Слияние Git не меняет сервер или телефоны. До отдельной публикации рабочий
Apps Script оставался v29. Отмена после переключения схемы требует
согласованного восстановления данных и кода, а не только старого deployment.
Если новые обслуживания уже записаны, нельзя восстанавливать снимок поверх них.
