# Синхронизация и уведомления

Точки входа описаны в [README connector](../app/src/main/java/ru/coffeepoint/core/sync/google/README.md).
Точные actions, JSON и проверки — в [реестре API](api-endpoints.md).

## Какие действия независимы

| Действие | Направление | Кто выполняет |
| --- | --- | --- |
| Отправка сохранённых пользователем изменений | Room → Apps Script → Sheets | Прямой запрос из репозитория |
| Доотправка неотправленных записей | Room → Apps Script → Sheets | `GoogleSheetsSyncWorker` |
| Получение актуальных данных | Sheets → Apps Script → Room | Ручное обновление или `StationAttentionWorker` |
| Получение продаж после заправки | Vendista → Sheets | Серверный триггер `StationSales.gs` |
| Создание начислений за вчера | Vendista → Sheets | Серверный триггер `DailyEarnings.gs` |

Обновление продаж на сервере не означает немедленный импорт на все телефоны.
`Обновлено:` на списке станций — время последнего успешного импорта на это
устройство, а не `salesUpdatedAt` из Sheets.

## Сохранение и повтор

Для станции и склада изменения сначала записываются локально. Изменённая
запись получает `isSynced=false` и локальный `updatedAt`. Успех запроса меняет
статус на `isSynced=true`, очищает `syncError` и `syncErrorType`.

При неудаче локальные значения остаются, а ошибка фиксируется отдельно.
Повтор отправляет сохранённое состояние; `updatedAt` нельзя заменять временем
каждой сетевой попытки. Фоновый воркер не является журналом бизнес-операций:
его источник — записи Room со статусом ожидания.

| Состояние | `isSynced` | `syncError` | `syncErrorType` |
| --- | --- | --- | --- |
| Изменено локально, попытки ещё не было | `false` | `false` | пусто |
| Успешно отправлено | `true` | `false` | пусто |
| Ошибка сети | `false` | `true` | `CONNECTION` |
| На сервере более свежая версия | `false` | `true` | `CONFLICT` |
| Другая ошибка | `false` | `true` | `UNKNOWN` |

Некоторые сценарии возвращают агрегированный результат нескольких сущностей.
Успех остатков не означает автоматический успех склада или станции.
Каталог обрабатывается отдельным репозиторием и в фоновую отправку не входит.

## Частичные обновления станции

| Сценарий | Что отправляется в `coffee_station` |
| --- | --- |
| Оператор завершил заправку | `complete_service`: `id,lastServiceDate,salesAfterService,salesUpdatedAt` |
| Снабженец обслужил узлы | `complete_service`: `id` и выбранные даты миксеров/контейнера |
| Изменение информации, аренды, ручной даты узла | `upsert` данных станции с локальным `updatedAt`; без серверных счётчиков продаж |

Локальные `pendingServiceOnly`, `pendingFullStationSync`,
`pendingSupplyServiceOnly`, `pendingMixersServiceDate`,
`pendingLiquidWasteContainerServiceDate` позволяют повтору сохранить нужный
состав полей. Их нельзя просто удалить, оставив общую отправку всей станции.

Серверный upsert физически записывает подготовленную строку, сохраняя значения
непереданных полей. `complete_service` обновляет отдельные ячейки.
Это разные механизмы; общий upsert не равен произвольной полной замене строки.

## Конфликты

`warehouse_stock.updatedAt` сохраняется сервером как настоящая дата Sheets,
если клиент передал время с явным часовым поясом. Отображение — `dd.MM.yyyy HH:mm`,
как в каталоге закупок; часовой пояс таблицы должен быть `Europe/Moscow`.
Например, `2026-10-22T06:38:06.664Z` виден как `22.10.2026 09:38`.
Секунды и миллисекунды не удаляются: API сериализует дату в ISO UTC,
а проверка конфликтов сравнивает полный момент времени.
Формат без явного пояса сохраняется как прежде. Для применения серверной правки
нужно обновить `SheetsRepository.gs` и versioned-развёртывание Apps Script;
изменение существующих ячеек само по себе не меняет будущую запись API.

Для обычного upsert сервер сравнивает `updatedAt`: если существующая запись
свежее входящей, возвращается ошибка `409` внутри JSON. Для `complete_service`
сравнивается соответствующая дата обслуживания.

Для склада `upsert_batch` проверяет все элементы до записи данных. Конфликт
одного элемента блокирует запись элементов этого пакета. Это не обеспечивает
откат при сбое Google Sheets во время последующей записи.

Воркер импорта может вызвать `resolveConflictBlocksForImport()`. Метод снимает
локальную блокировку с уже помеченных конфликтом записей и повторяет импорт:
удалённые значения могут заменить конфликтующие локальные. Ручного слияния
по полям или отдельного экрана разрешения конфликта пока нет.

## Импорт

### Перед началом заправки или обслуживания

Кнопка на экране станции сначала выполняет один `full_sync` с `stationId`.
Операторский сценарий запрашивает `coffee_station,station_inventory`,
снабженческий — `coffee_station,station_inventory,warehouse_stock`.
У управляющего состав зависит от выбранной кнопки, а не от роли.
`station_settings` и каталог не запрашиваются: настройки остаются локальными.
Между шагами процесс повторно не загружается, ввод не заменяется.

`GoogleSheetsServiceStartImporter` обновляет только выбранную станцию и её
остатки, склад — только в снабженческом процессе. Проверка локального состояния
перед записью и сама запись выполняются в Room-транзакции. Ожидающие изменения
станции/остатков блокируют замену; ожидающий склад проверяется только для
снабжения. Изменения во время GET также блокируют применение ответа.
Остальные станции, настройки и очередь отправки не очищаются.

Во время загрузки ввод заблокирован. При ошибке/блокировке пользователь может
повторить, отменить или явно продолжить локально с предупреждением о возможной
неактуальности. Показано время последнего общего импорта, а не время этого GET;
частичная загрузка не меняет общую отметку списка станций.

Это уменьшает риск старых данных при входе, но не защищает от последующего
изменения другим устройством: проверка исходной версии при сохранении пока
не реализована. Для серверной фильтрации обновить `Router.gs` и
`SheetsRepository.gs`, затем versioned-развёртывание. Со старым сервером клиент
выбирает нужную станцию из полученных строк, но ответ будет больше.

Перед импортом станций проверяются неотправленные станции, остатки, настройки,
склад и, если он включён, каталог. Если такие записи есть, возвращается
`SkippedPendingChanges`, чтобы не затереть ожидающие отправки данные.

После успешного получения непустого набора станций текущий импорт очищает
локальные таблицы станций, остатков и настроек и заполняет их заново. Каталог
при включённом импорте также заменяется. Склад добавляется/обновляется через
`insertAll`. Это не универсальная зеркальная синхронизация удалений всех листов.

Сотрудники и операции имеют отдельный импорт в `EmployeeSyncRepository`.
При первой сверке операций возможна замена локальной истории из Sheets;
присутствуют проверки ожидающих операций и пустого серверного ответа.

## Фоновые расписания

| Планировщик | Период | Работа |
| --- | --- | --- |
| `StationAttentionScheduler` | 1 час | Импорт станций/остатков/настроек/склада; после успеха — уведомления |
| `GoogleSheetsSyncScheduler` | 2 часа | Отправка ожидающих станций, склада, сотрудников, привязок и операций |
| `GoogleSheetsSyncScheduler.enqueueSync` | Разовая задача | Дополнительная доотправка по запросу кода |
| Apps Script / `StationSales` | 10 минут | Пересчёт продаж на сервере |
| Apps Script / `DailyEarnings` | Около 02:00, Москва | Начисления за предыдущий день |

Оба Android-воркера требуют подключённую сеть. WorkManager запускает задачи
не точно по часам: выполнение зависит от ограничений Android. Импорт при
неудаче запрашивает повтор. Воркер отправки запрашивает повтор при сетевых
ошибках или неожиданном исключении; известный конфликт сам по себе не означает
немедленный повтор с backoff.

## Уведомления

| Заголовок | Роли | Условие |
| --- | --- | --- |
| Станции требуют заправки | Оператор, управляющий | От 100 продаж либо от 10 дней после заправки |
| Требуется снабжение | Снабженец, управляющий | Критичные остатки станции либо срок миксеров/контейнера |
| Нужно пополнить склад | Снабженец, управляющий | Остаток ниже минимума; оба предела больше нуля |

Проверка использует последнюю сохранённую роль. При отсутствии роли отправки
нет. Для каждого типа постоянный ID, поэтому существующая карточка уведомления
обновляется. Канал `sales_refresh` имеет обычную важность; всплывающий баннер
не гарантирован. Настройки канала пользователя сохраняются Android.

Текущая зависимость: если импорт не прошёл или остались неотправленные данные,
сканирование уведомлений не выполняется. Для остальных узлов управляющего
отдельных уведомлений пока нет. Разбор: [известные ограничения](known-limitations.md).

## Диагностика

| Признак | Где искать причину |
| --- | --- |
| `UnknownHostException` | DNS/сеть до получения HTTP-ответа |
| HTTP `200`, но `success=false` | Ошибка приложения на стороне Apps Script, читать `error.status/message` |
| `SYNC_TOKEN ... not configured` | Script Properties, версия `Auth.gs` и используемое развертывание |
| `Sheet headers mismatch` | Порядок и имена первой строки листа относительно `Config.gs` |
| Данные давно не обновлялись | `StationAttentionWorker`: импорт, pending-записи, повтор, расписание |
| Данные локально остались `isSynced=false` | `GoogleSheetsSync`, результат нужной сущности и очередь WorkManager |

После публикации Apps Script запускаем проверку чтения
`scripts/Test-GoogleSheetsDeployment.ps1`. Токены и полные рабочие ответы
не включаем в документацию; текущие сетевые логи могут содержать токен запроса.
