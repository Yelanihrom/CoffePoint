# Заправка и снабжение

Одна feature содержит два независимых процесса, не две копии по ролям.
Управляющий запускает нужный процесс через существующую навигацию.

| Каталог | Ответственность |
| --- | --- |
| `refill/ui`, `refill/presentation` | Остатки и операторский чек-лист; завершение заправки через `complete_service` |
| `supply/ui`, `supply/presentation` | Сверка до пополнения, пополнение, контроль помола и обслуживание миксеров |
| `supply/model` | Черновик сверки/пополнения, источник списания и снабженческий чек-лист |
| `component` | Общие `ServiceStockCounters`, `ChecklistRow`, сохранённые компоненты фото |
| `model` | Общие количества остатков и модель пункта чек-листа |
| `presentation/ServiceStationViewModel` | Только чтение станции для заголовков последующих экранов, без записи и запросов Sheets |

`RefillStockViewModel` не читает склад и не содержит снабженческих состояний.
`SupplyStockViewModel` хранит оба первых шага в одном черновике: на первом
сверяются остатки, на втором вводится добавленное и источник списания.
Переход на второй шаг не сохраняет данные и не делает HTTP-запросов.
Итог станции — сверенное плюс добавленное, списание склада — только добавленное.
До сохранения можно вернуться назад; вручную заданное добавленное не теряется.

Сохранение станции и списание склада остаются одной транзакцией
`SupplierRefillRepository`. Повтор HTTP не повторяет списание в той же ViewModel.
Гарантии восстановления черновика после смерти процесса не добавлены.
Четвёртый этап (`SupplyChecklistViewModel`) сохраняет визит и начисление как
прежде, используя UUID из `SavedStateHandle`. Разделение пакетов не меняет
серверные методы, Room-схему, маршруты и логику начислений.
