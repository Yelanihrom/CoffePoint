# Сервер Apps Script

Файлы этой папки — версия серверного кода в репозитории. Android Gradle их не
собирает и не публикует. Для изменения рабочего сервера нужно перенести файлы
в соответствующий проект Apps Script и обновить развертывание HTTP API.

## Карта файлов

`full_sync` поддерживает необязательный `stationId`: строки `coffee_station`,
`station_inventory` и `station_settings` фильтруются по станции. Другие коллекции
не фильтруются и читаются только при выборе в `entities`. Для загрузки перед
обслуживанием обновить `Router.gs` и `SheetsRepository.gs`, затем развернуть
новую версию HTTP API; без `stationId` прежнее поведение сохранено.

| Файл | Ответственность |
| --- | --- |
| [Code.gs](Code.gs) | Входы `doGet` / `doPost` |
| [Router.gs](Router.gs) | Разбор запроса и выбор action |
| [Auth.gs](Auth.gs) | Проверка токена через Script Properties |
| [Response.gs](Response.gs) | JSON-оболочка успеха и ошибки |
| [Config.gs](Config.gs) | ID таблицы/папок, схемы листов, часовой пояс и ключи свойств |
| [SheetsRepository.gs](SheetsRepository.gs) | Чтение листов, upsert/пакет, конфликты, частичное обслуживание |
| [StationSales.gs](StationSales.gs) | Продажи после заправки и установка 10-минутного триггера |
| [DailyEarnings.gs](DailyEarnings.gs) | Ежедневное начисление сотрудникам и установка триггера |
| [VendistaClient.gs](VendistaClient.gs) | Общий запрос отчёта Vendista, retry и проверка неполного ответа |
| [SalesAnalytics.gs](SalesAnalytics.gs) | Продажи по станциям за произвольный период без записи в таблицу |
| [SupplyServiceVisits.gs](SupplyServiceVisits.gs) | Визит снабженца и начисление 2000 рублей одним Sheets API batch |
| [DrivePhotoStorage.gs](DrivePhotoStorage.gs) | Сохранённый модуль загрузки фото в Google Drive |
| [tests](tests) | Локальные Node.js-тесты сервера на таблицах в памяти |

## Настройки проекта Google

В **Настройки проекта → Свойства скрипта**:

| Свойство | Значение |
| --- | --- |
| `SYNC_TOKEN` | Тот же токен, что передаёт Android в `GoogleSheetsSyncConfig` |
| `VENDISTA_TOKEN` | Токен серверного доступа к отчётам Vendista |

В `Config.gs` проверить `SPREADSHEET_ID`, `ROOT_FOLDER_ID` и
`TIMEZONE = Europe/Moscow`. Все `.gs` относятся к одному проекту и используют
общие функции/константы. Наличие только нового файла без его зависимостей
может привести к ошибке вида `fetchVendistaSales_ is not defined`.

## HTTP API

Исправление ложных конфликтов дат обслуживания находится в `SheetsRepository.gs`:
`dd.MM.yyyy` разбирается до `new Date`, а нормализация миллисекунд затрагивает
только ISO-время. Для установки исправления заменить этот файл в Apps Script
и обновить версию существующего web-app развёртывания. APK, листы и триггеры
менять не нужно. Защита от действительно более новых дат сохранена.

Если вместо обновления существующего развёртывания создан новый URL, его нужно
указать в `GoogleSheetsSyncConfig.PRODUCTION_WEB_APP_URL` и выпустить новый APK.
Установленные приложения сами не меняют адрес сервера. Чтобы исправление
работало без обновления APK, обновляйте версию прежнего развёртывания,
сохраняя его URL.

Рабочие ветки локального роутера: `full_sync`, `upsert`, `upsert_batch`,
`complete_service`, `upload_photos`, `sales_analytics`, `complete_supply_visit`.
Проверка токена выполняется до action.
Ошибки возвращаются как `success=false` с `error.status` и `error.message`.

Настройки уведомлений подготовлены для обоих окружений: лист `notification_settings`
и изменения `Config.gs`, `SheetsRepository.gs`. `full_sync` возвращает
`notificationSettings`; `upsert`/`upsert_batch` используют ключ `role` и проверяют
boolean-флаги, допустимую роль и ISO UTC `updatedAt`. Частичная правка не очищает
остальные флаги; устаревшее время возвращает 409. Новый отдельный action не нужен.
Рабочие листы и колонки подготовлены 14.11.2026. Android использует одинаковые
методы в TEST/production без fallback между окружениями. Рабочий сервер обновлён
14.11.2026 через clasp до v27 с прежним URL; полный и выборочные импорты проверены.
APK ещё не выпущен. Тестовый сервер остаётся v8. Порядок и предварительные проверки — в
[инструкции публикации](../docs/production-backend.md).

В `SheetsRepository.gs` функции `employeeTimestampFields_`,
`normalizeEmployeeTimestamp_` и `employeeTimestampCell_` обеспечивают единое
хранение временных отметок сотрудников, привязок, операций и визитов как дат
Sheets. Отображение — `yyyy-MM-dd HH:mm:ss` по Москве; JSON — ISO UTC с
сохранением миллисекунд. Входящее время без зоны считается московским.
`SupplyServiceVisits.gs` использует тот же формат при атомарном append через
Sheets API. Изменение установлено в TEST и рабочем сервере v27.
Поля дат без времени этим правилом не затрагиваются.
HTTP-код ответа сам по себе не определяет успех операции.

Для экрана аналитики добавить `SalesAnalytics.gs` и обновить `Router.gs`.
GET `sales_analytics` принимает обязательную дату `startDate` и необязательную
`endDate` в формате `yyyy-MM-dd`. Границы дня — московские, без конечной даты
`DateTo` не передаётся в Vendista. Используются прежние `Config.gs`,
`SheetsRepository.gs`, `VendistaClient.gs` и Script Properties; новые листы,
поля и триггеры не нужны. После обновления кода опубликовать новую версию
существующего развертывания. Рабочее развертывание не обновляется из Git автоматически.

В Android также есть action `delete` для каталога. В текущих локальных
`Router.gs` / `SheetsRepository.gs` его реализации нет; это отдельный известный
пробел, а не рабочая ветка API. Полный реестр: [эндпоинты](../docs/api-endpoints.md).

`readHeaders` требует точного совпадения ожидаемых заголовков. `ensureHeaders`
при upsert умеет записать ожидаемые заголовки, но не переставляет данные под
ними. Поэтому перестройку колонок нельзя заменять простым повтором upsert.

## Триггеры

Визиты не используют триггеры: POST `complete_supply_visit` создаёт визит и
начисление по запросу. Требуется Advanced Google Service **Sheets v4** — зависимость
задана в `appsscript.json`. Для стандартного Cloud-проекта может потребоваться
включить Google Sheets API; владелец должен выдать запрошенные Google разрешения.
Обе строки сохраняются одним `Sheets.Spreadsheets.batchUpdate` под ScriptLock.
Повтор возвращает существующие записи, а другой сотрудник/станция/время с тем же ID
отклоняются. Ставка берётся с сервера; обычный upsert начислений визита запрещён.
ID начисления — обычный UUID: для нового начисления берётся клиентский `earningId`
или `Utilities.getUuid()`, а существующее ищется по `sourceType/sourceId`.
Автоматические `AUTO-EARNING-*` и UUID выплат не меняются.
Android вызывает обработчик на 4-м этапе и из исходящего воркера. Нужен
активный серверный снабженец; local-only профиль допустим только для локального TEST.
Подробности — [контракт визита](../docs/api-endpoints.md#визиты-снабженца).

| Функция установки | Устанавливаемый обработчик | Расписание |
| --- | --- | --- |
| `installEveryTenMinutesStationSalesTrigger()` | `refreshStationSalesEveryTenMinutes` | Каждые 10 минут |
| `installDailyEarningsTrigger()` | `recordYesterdayDailyEarnings` | Около 02:00 по Москве каждый день |

Установку выполнить вручную в редакторе один раз с выдачей разрешений.
Проверить список триггеров и журнал «Выполнения». Фактическое время ежедневного
запуска может отличаться от минуты 02:00.

Продажи считаются относительно текущего `lastServiceDate`. Перед записью
сервер проверяет, что за время запроса дата заправки не сменилась: устаревший
ответ не должен вернуть продажи до новой заправки. Формат `salesAfterService`
устанавливается как целочисленный.

Начисление за вчера учитывает активных операторов, начало работы, привязки
и исключение станции из заработка. ID записи
`AUTO-EARNING-{employeeId}-{date}` позволяет обновлять тот же день без дубля.
Пропущенные исторические дни автоматически отдельной очередью не догоняются.

## Проверка и публикация

Из корня репозитория:

```powershell
node --test google-apps-script/tests/http-contract.test.cjs
```

После сохранения файлов обновить существующее развертывание через
**Развернуть → Управление развертываниями → карандаш → Новая версия**.
Существующий URL сохранится. При создании нового развертывания его URL
нужно отдельно перенести в Android и собрать APK заново.

Триггеры используют сохранённый код проекта; опубликованный versioned `/exec`
использует выбранную версию развертывания. Сохранения файлов в редакторе
недостаточно, чтобы обновить эту версию HTTP API.

Проверка живого API только чтением:

```powershell
# Сначала настроить COFFEEPOINT_SYNC_TOKEN в окружении.
.\scripts\Test-GoogleSheetsDeployment.ps1 -WebAppUrl 'https://script.google.com/macros/s/DEPLOYMENT_ID/exec'
```

Ограничения синхронизации: [общее руководство](../docs/synchronization.md).
Схема: [модель данных](../docs/database.md).
