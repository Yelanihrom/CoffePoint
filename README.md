# CoffeePoint

Android-приложение для работы с кофе-станциями: заправка, снабжение, обслуживание,
склад, каталог закупок, взаиморасчёты с сотрудниками и аналитика продаж по станциям.

## Запуск проекта

1. Открыть корень репозитория в Android Studio и дождаться Gradle Sync.
2. Установить Android SDK, указанный в [app/build.gradle.kts](app/build.gradle.kts).
   Сейчас `compileSdk` и `targetSdk` равны 37, минимальный API устройства — 26.
3. Использовать JDK 21 для Gradle. Android Studio может предоставить его через `jbr`.
4. Для локального тестирования выполнить `node scripts/configure-studio-test.cjs`:
   он создаёт игнорируемый `test-backend.properties` с тестовым deployment и
   локальным токеном. Подготовка доступов описана в [тестовом стенде](docs/test-environment.md).
5. Выполнить Gradle Sync, выбрать вариант `debug`, эмулятор или телефон и
   запустить конфигурацию Android App для модуля `app` через Run.

Обычный debug Run использует `ciBuild=true`: приложение **CoffeePoint TEST**,
отдельный пакет `ru.coffeepoint.ci`, жёлтая «Т» на иконке, отдельная БД и только
тестовый сервер. Без тестовых настроек синхронизация отключена, перехода на
рабочую таблицу нет. Release всегда использует рабочий сервер.

`local.properties`, ключи подписи, пароли и APK исключены из Git.
Значения рабочих токенов в документацию не добавляем.

## Проверки и сборка

В Studio доступны общие Gradle-конфигурации **TEST** и **MAIN**: они собирают
debug APK с тестовым и рабочим окружением соответственно, без установки на
устройство. Подробности — в [тестовом стенде](docs/test-environment.md).
MAIN не является подписанным рабочим release.

В PowerShell из корня проекта, с примером пути к JDK на Windows:

```powershell
.\scripts\Test-Api.ps1 -JavaHome 'D:\Android Studio\jbr'

$env:JAVA_HOME = 'D:\Android Studio\jbr'
.\gradlew.bat :app:assembleDebug
```

APK: `app/build/outputs/apk/debug/app-debug.apk`.
Для release-сборки и обновлений поверх установленного приложения см.
[руководство по выпуску](docs/releases.md).

Продажи станций и ежедневные начисления получает сервер Apps Script.
В версии **1.0.25** добавлен заработок снабженца для TEST и production:
каждый новый завершённый визит на 4-м этапе создаёт начисление 2000 рублей.
Повторы не дублируют начисление; заработок и выплаты доступны через иконку денег
в режиме снабжения. Визиты подтверждаются через `complete_supply_visit`, выплаты
отправляются отдельно; при отсутствии сети очередь хранится в Room для воркера.
Рабочий сервер обновлён 14.11.2026 до версии 27 через clasp, URL сохранён;
Android использует это же рабочее развёртывание. В рабочем `employees`
добавлен активный Денис с ID 2; тестовые визиты и финансовые операции не переносились.
Из Android напрямую в Vendista отправляются только команды терминалу.

## Аналитика и обслуживание

Раздел Управляющего «Аналитика» открывает два подраздела: «Продажи» с прежним
отчётом за период и «История обслуживаний» с визитами снабженца. История
показывается из Room, обновляется существующим импортом и доступна без сети.
Есть отдельный фильтр «С / По», по умолчанию с начала текущего месяца.
Явные загрузки и сохранения используют единый блокирующий индикатор.

Исправлен ложный конфликт при сохранении обслуживания миксеров: сервер теперь
однозначно разбирает даты `dd.MM.yyyy`, включая дни с 1-го по 12-е. В приложение
включён новый адрес рабочего Apps Script. Установленные версии со старым URL
нужно обновить, если прежнее развёртывание отдельно не обновлялось.
Подробности и проверки — в [синхронизации](docs/synchronization.md).

Уведомления о заправке, снабжении и складе повторяются не чаще раза в **6 часов**
для каждого типа на устройстве, независимо от роли. Первый показ не откладывается;
фоновый импорт данных остаётся ежечасным. Уведомления об обслуживании узлов по умолчанию
получает только Управляющий; роли и типы настраиваются в «Настройки → Уведомления»
и синхронизируются с Sheets. В уведомлениях используется адрес станции.
Правила — в [синхронизации](docs/synchronization.md).

У Управляющего в главном меню доступны Оператор, Снабженец, **Аналитика**
и **Каталог закупок**. Каталог открывается четвёртой плиткой, а не иконкой
в верхней панели снабженческого списка станций.
Аналитика показывает общий итог и продажи по каждой станции за выбранный
период. По умолчанию — с первого числа месяца в 00:00 по Москве по текущий
момент, без конечной даты. Отчёт получает Apps Script, не Android; он не меняет
остатки, счётчики после заправки или начисления сотрудникам.
Для собственного периода можно выбрать обе даты; кнопка «По текущий момент»
удалена. Дата окончания включает выбранный день до 23:59:59 по Москве.

Для аналитики сервер должен содержать [SalesAnalytics.gs](google-apps-script/SalesAnalytics.gs)
и обновлённый [Router.gs](google-apps-script/Router.gs), а Script Properties —
`SYNC_TOKEN` и `VENDISTA_TOKEN`. После обновления файлов требуется новая версия
существующего web-app развертывания. Выпуск APK не публикует сервер автоматически.
Безопасная диагностика Android — тег Logcat `SalesAnalytics`, без токенов и URL.

В снабженческом процессе четыре шага: пополнение, проверка фактических остатков,
контроль помола и обслуживание. Зелёная зона помола — **3–6 импульсов/с**.
В последнем шаге обязательны мытьё миксеров и общий тест системы: отсутствие
скрипа УЗК, поступление воды в каждый миксер и отсутствие ошибок на экране.
Очистка/продувка УЗК исключена из чек-листа снабженца.
Завершение обновляет только дату миксеров, не дату ТО УЗК/контейнера.
Полные инструкции и правила сохранения — в [бизнес-процессах](docs/business-processes.md).

Документация описывает исходники; актуальный номер версии берётся из Gradle и
проверяется автоматически в [руководстве по выпуску](docs/releases.md).
Код в GitHub, установленный APK и опубликованное развертывание Apps Script
обновляются отдельными действиями и могут иметь разные версии.

Для сервера подготовлен отдельный ручной workflow **Production Apps Script**:
preflight без записи по умолчанию, публикация из SHA master, резервная версия
и проверка API. Он ещё не запускался на рабочем окружении: автоматизация
отложена, текущий сервер опубликован вручную через clasp. Настройки и порядок
описаны в [инструкции](docs/production-backend.md).
