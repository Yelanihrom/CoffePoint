# CoffeePoint: инструкции для агента

## Начало работы

- Сначала проверь рабочую ветку и незакоммиченные изменения. Новые изменения
  делай в `test`; не отправляй их напрямую в `master`. Слияние, тег и рабочий
  релиз требуют подтверждения пользователя. Не откатывай чужие изменения.
- Перед правкой прочитай соответствующий код и документ из карты ниже.
  Документация помогает найти контекст, но при расхождении проверяй реализацию
  и исправляй описание. Не считай историю чата единственным источником требований.
- Отвечай пользователю по-русски. Документы и пользовательский текст сохраняй
  в UTF-8, проверяй кириллицу после изменения строк.

## Что нельзя случайно изменить

- Продажи и ежедневные начисления получает Apps Script. Не возвращай запросы
  продаж в Android. Прямой Vendista-клиент оставлен для команд терминалу;
  в CI-сборке эти команды намеренно заблокированы.
- Завершение заправки оператора отправляет узкий набор полей станции через
  `complete_service`. Снабженец обновляет только выбранные узлы обслуживания.
  Не заменяй эти операции общим upsert строки и не сбрасывай продажи снабженцем.
- Импорт/проверка уведомлений и отправка pending-изменений — разные воркеры.
  Не дублируй отправку в импортирующем воркере.
- При сетевой ошибке сохраняются локальные изменения и статусы синхронизации.
  Повтор запроса не должен повторно списывать склад. Перезапуск процесса и
  конкуренция устройств пока не полностью покрыты: не обещай гарантии без тестов.
- Взаиморасчёт — все начисления минус все выплаты сотруднику; выбранный период
  истории его не ограничивает. Ручное начисление из приложения удалено.
- Модуль камеры сохранён по явному решению пользователя. Не удаляй его как легаси.

## Окружения и секреты

- Тестовая сборка включается только с `-PciBuild=true`, имеет отдельный
  applicationId и использует только тестовый URL/токен. Не добавляй fallback
  на рабочий сервер, не ослабляй блокировку команд терминалу ради тестов.
- `.codex`, ключи подписи, OAuth-файлы, токены и локальные properties не коммить.
  Не выводи секреты, полные авторизованные URL или HTTP-тела с токенами в логи.
- Для тестового сервера запускай `scripts/prepare-test-backend.cjs` или
  `scripts/Invoke-TestClasp.ps1`. Комплект генерируется в `.codex/apps-script-test`;
  не редактируй его как исходник. Правь серверный код или генератор.
- Без явной задачи на рабочее окружение не пиши в рабочую таблицу, не обновляй
  рабочее развёртывание и не устанавливай его триггеры. Перед live-записью
  проверь тестовые Script ID, deployment ID и spreadsheet ID по конфигурации.
- Не запускай изменяющие live-тесты на общих данных без восстановления,
  защиты от параллельного запуска и явного понимания затронутых записей.

## Проверки

Из корня проекта, Node.js 22+:

```powershell
node --test scripts/tests/docs.test.cjs scripts/tests/test-backend.test.cjs google-apps-script/tests/http-contract.test.cjs
node scripts/docs.cjs --check

$env:JAVA_HOME = 'D:\Android Studio\jbr'
.\gradlew.bat :app:testDebugUnitTest :app:assembleDebug -PciBuild=true --console=plain
```

Путь к JDK — пример для текущего компьютера; при другом окружении используй
доступный JDK 21. Если Node.js не в PATH, найди установленный или bundled runtime;
не считай отсутствие команды доказательством отсутствия самого runtime.
Без тестовых переменных CI APK собирается, но не синхронизируется.

- Изменение запросов: обе стороны контракта и соответствующие JVM/Node-тесты.
- Изменение бизнес-правила: тесты границ, нулевых значений, ролей, дат и повторов
  в затронутом сценарии. Не ограничивайся успешной компиляцией.
- Изменение схемы: Room, миграции, сервер и независимый JSON-контракт
  `app/src/test/resources/contracts/sheet-schema.json`.
- Только документация: проверка ссылок/версии и тесты скрипта при его изменении;
  пересборка APK не нужна.
- В отчёте различай локальные проверки, GitHub CI, live API и ручную проверку
  интерфейса. TODO/skip не называй покрытым сценарием.

## Документация вместе с кодом

- Меняешь поведение, API, схему, расписание или сборку — обновляй соответствующие
  документы в том же PR. Исправил ограничение — скорректируй список ограничений.
- После изменения версии в Gradle выполни `node scripts/docs.cjs --write`.
  Генерируемый блок в `docs/releases.md` вручную не редактируй.
- Этот файл хранит короткие правила и навигацию, а не полный журнал работы.
  Новые подробности добавляй в профильные документы и ставь ссылки здесь,
  только если это помогает следующему агенту найти нужный контекст.
- Источники документации и исходники публикуются через `test`. Публикация Git
  не обновляет APK на устройствах или сервер Apps Script автоматически.
